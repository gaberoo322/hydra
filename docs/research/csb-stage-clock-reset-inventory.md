# CSB: which pending changes reset a Stage Clock if they land after Stage A's day 0

Research for hydra#5226 (wayfinder map #5225). Evidence read from `gaberoo322/claw-street-bets` `main` at `04d45b3` (2026-10-24); paths below are relative to that repo. Nothing here is a decision: it is the inventory the grilling ticket #5228 ("which config changes land before day 0, one bump or several") consumes.

## 1. The reset rules (what decides each row)

| Rule | Source | Effect |
|---|---|---|
| R1 Version pin | `direction/outcomes.yaml` L34-36; `config/risk-template.json` `_operatorOnly`; `config/graduation-gate.yaml` header | A bump of `risk-template` or `graduation-gate` `version` resets **every** stage clock. |
| R2 Frozen-Parameter Protocol | `CONTEXT.md` L247-248; `config/frozen-granularity.yaml` header | A Strategy's parameters (incl. entry granularity) are fixed at stage start; any later edit resets **that Strategy's** Stage Clock. A parent re-freeze also resets its Filtered Twin (`CONTEXT.md` L116; `graduation-gate.yaml` `regime_filters...parent_refreeze_resets_clock`). |
| R3 Cost Model re-freeze | `graduation-gate.yaml` `cost_model.refreeze` | Only at a stage boundary, on three triggers (venue fee-schedule change, realized tier below advanced-2, slippage median above frozen); effect: stage clock resets. |
| R4 Fill-Model Honesty | `graduation-gate.yaml` `fill_model_honesty`; `src/graduation/fill-model-honesty.md` 3.2-3.4 | Breach: halt, fix the Fill Model (PR on `src/fill-model/`), **Roster-wide** clock reset on the fix merge; divergent-period trades excluded forever (marked, not deleted). A tolerance edit is a gate bump (R1). |
| R5 Stage definition | `CONTEXT.md` L232 | A stage's clock resets on "a parameter edit, a config version bump, or a Fill-Model Honesty breach". Nothing else is listed. |

Corollary: code that is not an input to R1-R5 (Operator-Only config values, frozen parameters, Fill Model behaviour, Cost Model) is clock-safe by definition, however money-critical it is. Money-critical is a review class (`riskCritical.surface`), not a clock rule.

**Mechanical enforcement is thin.** Day 0 is the Trial Ledger row's `entered_at_ms` (`src/db/schema.ts` `trial_ledger`), keyed by `frozen_parameter_hash`. The row records no gate version, risk-template version or Fill Model version. `checkStagePreconditions` (`src/graduation/stage-preconditions.ts`) only checks that the gate's `risk_template_version` equals the template's `version` at evaluation time. So a post-day-0 bump is not auto-detected as a reset; the operator must close the open trial row and open a new one by hand, and a forgotten reset silently keeps a stale clock. `fill-model-honesty.md` 5 Q4 (Fill Model version on trial rows) is still open. This is why "land before day 0" is the safe default, not merely a preference.

## 3. Answers to the ticket's questions

1. **Clock-resetting if landed after day 0:** (a) any `risk-template.json` `version` bump or any value change under it other than an additive no-op field, including a Roster aggregate Daily-Loss ceiling field; (b) any `graduation-gate.yaml` edit (fee re-freeze, tolerance, regime filter, new Roster slug); (c) any `frozen-granularity.yaml` edit after the freeze; (d) a Fill Model change (`src/fill-model/`), which resets the whole Roster via R4 3.3.
2. **Clock-safe:** Stage Evaluator completion, Fill-Model Honesty enforcement code, the SCAFFOLD edit, `order_intents` write-ahead, DMS wiring, dashboard and outcome writers, live-adapter work, and `long_only` **if** the operator rules that additive fields are not bumps (a single ruling is needed: #66 and the roster-cap note point in opposite directions).
3. **Retroactive application:** exclusion of divergent-period trades is retroactive by design (R4 3.4, marked not deleted). Nothing else is: a config bump cannot be backdated, and the Trial Ledger holds no version columns to prove which config a stage ran under.

## 4. What this means for the map

- Hard pre-day-0 set: the 4-slug freeze (with sweep evidence), plus any template or gate edit the operator wants (the `long_only` ruling; a gate audit for evaluator-required fields; whether a Roster aggregate Daily-Loss ceiling is wanted at all). One combined bump versus several is #5228; a single bump is strictly cheaper, since every bump before day 0 is free and every one after is a restart.
- Cheap hardening to price in #5228: record gate version, risk-template version and a Fill Model version on the Trial Ledger row so post-day-0 resets are mechanical (closes `fill-model-honesty.md` 5 Q4). Adding columns is a migration, hence clock-safe.
- Not verified here: whether #177 and #194 have remaining scope touching the gate (read titles and the merged-PR trail, not every child), and whether priorities #6 and #7 have shipped. Re-check before #5228 closes.
