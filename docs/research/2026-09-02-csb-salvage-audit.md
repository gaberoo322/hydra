# Salvage audit: what CSB reuses from hydra-betting

Resolves #4321. Read-only sweep of `/home/gabe/hydra-betting` (app code root `web/src`) to decide what carries over to **CSB (Claw Street Bets)** — the new autonomous intraday crypto trading system: one venue adapter, an OWNED fill simulation shared across backtest/paper/live, TS + Next.js + Postgres + systemd, app scaffolded at the repo root (reversing betting's `web/` subdir layout), and five risk invariants (server-side stops on every entry, per-trade risk %, daily loss halt, dead-man's switch, credential fence). CSB is scaffolded fresh; nothing here is copied verbatim without a stated adaptation.

Verdict legend: **REUSE-AS-IS** (pattern/convention ports directly, rename only) · **ADAPT** (structure is right, content is betting-specific and needs rework) · **DO-NOT-CARRY** (retired, dormant, or arbitrage/cross-venue-specific — no CSB equivalent).

## 1. Venue/provider adapter seam

hydra-betting has **no formal `Venue` TypeScript interface** — "adapter" is a directory convention, not a type contract. Each venue gets its own directory under `web/src/lib/providers/<name>/` split into auth / rate-limiter / normalization / errors / client-factory submodules, and a separate per-venue **executor** (`web/src/lib/execution/kalshi-executor.ts`, `polymarket-executor.ts`, ~78KB/53KB respectively — the largest files in the repo) that writes to the one shared `venue_orders` table. `web/src/lib/providers/CONTEXT.md` codifies the **Venue** (order-submittable) vs **MarketDataSource** (read-only signal feed) distinction and states the foundational rule: adapters are never deleted even with zero callers (CLAUDE.md rule #1).

| Item | Verdict | Rationale |

## 2. Execution guardrails → CSB's five risk invariants

This is the strongest reuse area. hydra-betting's single-leg **directional** execution path (M13, the survivor of the ADR-0002 cross-venue-arbitrage retirement) is architecturally close to what CSB needs: one venue, one leg, explicit fail-closed gates composed in front of a submit call.

The Kalshi ticker-regex fence bundled in the same file is venue-specific and has no CSB analogue as a regex, though a symbol/pair allowlist could reuse the "source-frozen, test-pinned allowlist" shape. |

| `execution/directional-*` chain (nomination → plan → persist → execute, `DirectionalPaperExitCriteria`) | ADAPT | Server-side stops / entry gating | The *sequencing pattern* — pure contract gate → pure sizing → I/O persist → one discriminated result, short-circuiting on first rejection, no DB write on a rejected candidate — is the right shape for CSB's own entry pipeline. **Gap worth flagging explicitly:** CSB's brief calls for an **OWNED fill simulation shared across backtest/paper/live**. hydra-betting does **not** have this — its "paper mode" (`directional-single-leg-persist.ts`) synthesizes a fully-filled receipt at the planned price with zero slippage/partial-fill/fee model by construction (`requestedCount === filledCount`, fees zero, status resolves straight to `executed`), explicitly documented as a simplification, not a real simulator. **Nothing in hydra-betting satisfies CSB's fill-simulation requirement — it must be designed and built new.**

## 3. Risk/staking machinery

The de facto staking/position-sizing machinery lives across `web/src/lib/risk/`, `web/src/lib/wagers/`, `web/src/lib/bankroll/`, and sizing logic embedded in `web/src/lib/execution/`.
