## Summary

Raises the two dispatch-outcome retention constants in `src/redis/dispatch-outcomes.ts` so the `hydra:autopilot:dispatch-outcome:*` plane can serve as the cross-run trend substrate on wayfinder map #3925 (decided in #3928):

| constant | before | after |
|---|---|---|
| `DISPATCH_OUTCOME_TTL_SECONDS` | `14 * 24 * 3600` (14d) | `90 * 24 * 3600` (90d) |
| `DISPATCH_OUTCOMES_INDEX_MAX` | `2000` | `8000` |

There is **no backfill** — everything past the current 14-day horizon is already TTL-reaped, so the raise is **prospective only** and the 90-day clock starts the day this merges (issue #3962). At the measured 14.3 records/day / 135 B payload, 90d costs ~0.17 MiB (~0.02% of the 768 MB maxmemory headroom), so cost is not a consideration; 8000 keeps the cap non-binding past a year while remaining a real runaway valve. The module's invariant is preserved unchanged — *TTL is the primary reaper; the index cap is a runaway safety valve* (the opposite of the ledger's never-trim rule) — only the numbers move.

`DISPATCH_OUTCOMES_INDEX_MAX` is now `export`ed so the regression test can pin the literal.

The coupled constant `CASCADE_OUTCOME_WINDOW_MS` in `src/redis/cascade-telemetry.ts` is **left at 14d** (widening it changes cascade's cost-delta/merge-rate fold semantics — out of scope). Its docstring previously *asserted the window equals the TTL*; that claim is now false (14d window vs 90d TTL), so the docstring is corrected to state the real invariant — **window ≤ TTL** — rather than equality. The functional invariant holds: a 14d window against a 90d TTL never asks for records the plane has already reaped.

Tier: 3 (operator-review change — src/redis/dispatch-outcomes.ts, src/redis/cascade-telemetry.ts, test/dispatch-outcomes.test.mts)

Closes #3962
