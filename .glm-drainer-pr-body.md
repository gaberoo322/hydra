## Summary

Dashboard v3 slice gamma (#4008, epic #4005, ADR-0034): the **/health page** — the only phone-grade surface, answering *is it on fire, or burning money?* with nothing that needs reading.

- **DeployAxes** renders deploy state as **two orthogonal axes** — *drift* (deployed SHA vs origin/master) and *health* (service actually working) — never one combined light. Drift is computed **client-side** from the two raw SHAs the server ships verbatim (ADR-0034 §5 rule 3); a null SHA renders UNKNOWN, never a confident in-sync/drifted claim.
- **GET /health/deep is surfaced** (dark until now): status chip + api/redis/scheduler/systemd lights.
- **CostPanel**: 24h token burn, tokens-per-merged-PR, and weekly quota burn — three figures, each from its own endpoint with its **own server generatedAt**, never blended.
- **Actions relocated from the /now Console**: pause/resume (single-click, server-confirmed) and the **emergency brake** (explicit second confirm action before the POST fires). Both re-render only once the follow-up read confirms the write.
- **Trust seam (slice alpha #4006) everywhere**: `/health` and `/health/deep` gain machine-readable `generatedAt` (checkedAt kept, aliased); a Redis read failure on `emergencyBrake`/`autopilotPause` now surfaces an additive `ok:false` sibling flag instead of silently defaulting to the confident-looking `{engaged:false}`/`{paused:false}` shape; the two cost endpoints each stamp `generatedAt`. Panels render UNKNOWN / stale via the shared `derivePageStatus` machine.

Closes #4008

Tier: 3 (operator-review change — src/api/health.ts, src/health/deployed-sha.ts, src/api/metrics-cost.ts, +2 more)
