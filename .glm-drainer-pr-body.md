Closes #3851

## Summary

Broadens the in-flight dev-work exclusion in `scripts/autopilot/collect-state.sh` so a non-closing `Refs #N` PR-body reference is recognised as evidence that an anchor is already being built. The exclusion's open-PR body matcher previously only recognised GitHub *closing* keywords (`Closes`/`Fixes`/`Resolves #N`); a deliberate non-closing `Refs #N` — the correct choice for a draft PR that must not auto-close its issue — was invisible to it, and the sibling branch-name source could not rescue a harness-created `worktree-agent-<hash>` branch (no issue number in that name). All three evidence sources therefore missed open draft PR #3802 (body `Refs #3708`) and `orch_dev_ready_anchor` promoted #3708 — a duplicate build on work already awaiting review (autopilot run ba2f8cdc, turn 3).

Fix: add `refs?` to the body-keyword regex alternation. Deliberately NOT changed: a bare `#N` is still ignored (a passing mention like "blocked on #3749" must not false-exclude and starve dev_orch), and the `worktree-agent-*` branch source still carries no issue number by design.

Tier: 3 (operator-review change — `scripts/autopilot/collect-state.sh` is T3 infra per ADR-0004; the test file inherits)
