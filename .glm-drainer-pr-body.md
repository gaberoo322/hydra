## Stamp the anchor reference onto the dispatch-outcome record (issue #3971)

closes #3971
Tier: 3 (operator-review change — src/redis + src/autopilot; live classifier `GET /api/tier?files=...`)

### Summary

`DispatchOutcomeRecord` carried no anchor/issue field, so no code path could
attribute a recorded token figure to a GitHub issue — the final rung of the
attribution ladder (run → turn → class → skill → **issue**) was missing. This
adds an `anchorReference: string | null` field to the record and stamps it once
at first write (`writeDispatchOutcomeRecord`) from `CycleRecordBody.anchorReference`,
which reap.py already forwards as the positional `anchor_ref` (issue #2012 — the
value has been in hand at the write site all along). Dark-tolerant: a dispatch
with no resolvable anchor records `null`, never a fabricated or guessed value
(the #2822 never-guess convention already governing `runIdPrefix`).

The field is write-once and identity-adjacent (like `runIdPrefix`/`turn`/
`className`): it is **not** added to `DispatchOutcomePatch` or the upgrade path.
`src/autopilot/schemas.ts` needs **no change** — `CycleRecordBodySchema` already
declares `anchorReference: z.string().optional()`; it is listed in scope
defensively, not because it was missing.
